# 評価の手順

## 1. 評価一式 (suite) は版で管理する

評価は研究とともに変わる。変わること自体は止めず、**1 つの比較の中では評価を変えない**ことだけを守る。

- 問題集・評価モード・指標・閾値をまとめて `bench/suites/vN/suite.toml` に書く (`bench/README.md`)。
- **一度使い始めた版は変更しない。** 変えるときは次の版を作る。
- 施策の提案書に、どの版で測るか (`x-suite: v1`) を書く。数字は必ず版とセットで読む。
- 新しい版には、できるだけ前の版の問題集も含める (系列が途切れないように)。

## 2. 評価の変更も施策にする

- 評価一式を変えるときは `kind: bench` の施策を立てる。手順はほかの施策と同じ。
- **モデルの変更と評価の変更を、1 つの施策に混ぜない。**
- 新しい版を採用するときは、同じ施策の中で、基準線と現在の最良のものを新しい版で測り直す。それが終わるまで採用としない。

## 3. 問題ごとの出力を残す

評価では集計値だけでなく、問題 (サンプル) ごとの出力を残す。指標は、残した出力から計算できるようにしておく。指標を足すときに、再学習も再推論も要らなくなる。

## 4. 予算の段階 (tier)

段階の名前と使い方は共通。規模の目安は、プロジェクトの最初の施策で決めて `bench/README.md` に書く。

| 段階 | 目的 |
|---|---|
| smoke | 動くかどうか。承認の前でも回してよい |
| probe | 候補をふるいにかける |
| screen | 見込みがあるか。seed 1 個 |
| confirm | 採用してよいか。本番の規模、seed 複数 |

- **採用の判定には confirm が必要。** screen までの結果では採用しない。
- 不採用の判定は screen で出してよい。ただし差が誤差の範囲なら `parked` にする。

## 5. 基準線と誤差

- **基準線は、同じ版・同じ段階・同じ種類のマシンで測り直す。** 過去の施策の数字を流用しない。
- 差を言うときは、信頼区間 (ブートストラップなど) か seed 間のばらつきを必ず出す。区間が重なる差は「差なし」として扱う。
